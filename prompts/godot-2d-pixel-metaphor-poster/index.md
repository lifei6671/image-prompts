````text
# Godot 2D 像素隐喻海报

## Prompt

```text
创作一张具有思想表达的 Godot 2D 独立游戏像素风视觉隐喻海报。

不要把“{{主题原文}}”逐字翻译成插图，也不要先套用固定的游戏场景模板。

先理解主题背后的：
核心观点，
深层含义，
主要矛盾，
情绪状态，
因果关系，
人与系统之间的关系，
最值得被看见的一层含义。

然后将这个抽象观点转译成一个“玩家可以亲自体验”的二维游戏关卡。

整张图只通过一个清晰的游戏机制隐喻表达主题。

最终效果不是游戏截图、概念草图或普通像素插画，
而是一张具有完整世界观、关卡逻辑、环境叙事和专业标题层级的独立游戏宣传海报。

【输入】
主题 / 主标题：{{主题原文}}
图片比例：{{16:9 / 3:2 / 4:5 / 9:16 / 1:1 / 自定义}}
用途：{{公众号封面 / X 封面 / 小红书封面 / 视频封面 / 海报 / 自定义}}
可选补充语境：{{可留空}}
可选情绪倾向：{{可留空；默认根据主题判断}}
可选禁止元素：{{可留空}}

【核心原则】
整张海报只保留：

1 个最重要的观点，
1 个主要角色，
1 个明确动作，
1 个核心机制，
1 个目标或阻碍，
1 个核心象征物，
1 个视觉焦点，
1 个主要视觉隐喻，
1 块合理留白区域。

不要同时解释主题的所有含义。

一个准确、可体验的机制关系，
优先于多个漂亮但互不关联的像素元素。

【主题理解】
在生成前内部完成以下判断，但不要展示分析过程：

主题表面在说什么？
真正想表达什么？
最核心的冲突是什么？
最主要的情绪是什么？
谁正在面对什么？
什么力量在阻碍或推动角色？
这个关系最像哪一种游戏机制？

按照：

抽象概念
→ 具体处境
→ 游戏机制
→ 可体验关卡
→ 视觉隐喻

完成转译。

最终选择最容易一眼理解、视觉冲击最强、最适合单张海报表达的一个方向。

【机制优先】
场景首先要像一个可以实际游玩的关卡。

角色的处境必须通过：
移动，
阻挡，
距离，
重复，
攀登，
坠落，
选择，
资源，
建造，
光暗，
路径变化
或环境规则体现。

不要使用一组解释型图标告诉观众主题是什么意思。

应该让观众看到场景后产生：
“如果我是这个角色，我正在经历什么？”
这样的直觉。

【游戏机制隐喻词典】
以下内容只是关系词典，不是固定模板。

根据主题选择其中最准确的一种，也可以重新设计其他机制。

方向冲突：
使用反向道路、逆向传送带、移动平台、错误箭头、倒退路径或逐渐远离的终点。
适合表达：
方向错误，
越努力越远，
追错目标，
系统力量与个人行动相反。

距离关系：
使用远方城堡、山顶、出口、桥梁、阶梯、灯塔、遥远建筑。
适合表达：
长期目标，
时间积累，
长期主义，
遥远但明确的价值。

尺度反差：
使用一个微小角色面对巨大机器、巨塔、城市、系统、怪物或巨大结构。
适合表达：
人与 AI，
人与时代，
个体与系统，
个人与规则，
技术力量差异。

循环困境：
使用环形道路、无限楼梯、重复房间、闭环地图、重复机关。
适合表达：
内耗，
重复劳动，
路径依赖，
无法突破，
系统循环。

光暗对比：
使用黑暗区域中的单一出口、火焰、窗口、森林入口、远方光源。
适合表达：
希望，
觉醒，
选择，
转折，
未知中的方向。

建造与积累：
使用逐渐形成的城堡、图书馆、基地、技能树结构、升级建筑、资源仓库。
适合表达：
知识，
成长，
复利，
长期积累，
能力建设。

信息与注意力：
使用数据洪流、通知怪物、噪音区域、安静森林、隐藏房间、被信息包围的角色。
适合表达：
AI 时代，
信息洪流，
注意力，
专注，
认知过载。

资源取舍：
使用有限钥匙、有限桥梁、能量节点、岔路、必须放弃的资源。
适合表达：
选择，
机会成本，
时间，
资源分配。

系统规则：
使用不可跨越边界、自动移动地形、规则化机关、隐形墙、不断变化的地图。
适合表达：
制度，
算法，
规则，
组织结构，
环境约束。

【隐喻选择】
不要机械匹配关键词。

例如：
“成长”不必一定画升级，
“AI”不必一定画机器人，
“焦虑”不必一定画怪物，
“长期主义”不必一定画山顶。

先理解具体语境，再确定机制。

如果多个方案都成立，
优先选择：

最简单的，
最容易体验的，
视觉反差最大的，
最适合单张图片的，
在缩略图中仍然清楚的。

【主角】
画面只有一个主要角色。

角色必须有明确动作，例如：
向前走，
停下，
跳跃，
攀登，
推东西，
奔跑，
观察，
回头，
修建，
躲避，
站在边缘，
面对目标。

角色动作需要直接表达与关卡机制的关系。

角色不需要复杂人物设定。

保持清晰的像素轮廓和统一 Sprite 比例，
让人物在小尺寸下仍能被辨认。

不要加入第二个同等权重主角。

如果确实需要其他人物，
只能作为极小环境 NPC 或背景参照，
不得形成第二故事线。

【目标或阻碍】
必须存在一个明确目标或阻碍。

例如：
远处出口，
巨大机器，
城堡，
无法跨越的断层，
终点门，
高塔，
巨型墙体，
黑暗区域，
正在关闭的门，
无限循环结构。

目标或阻碍需要在构图中占据明确位置。

观众应该能够快速理解：
角色正在去哪里，
或者什么东西阻止了他。

【单一场景】
只设计一个完整关卡场景。

环境可以丰富，
但所有元素都服务同一个游戏机制。

可以出现：
平台，
道路，
草地，
森林，
山体，
废墟，
城市，
机器，
建筑，
洞穴，
数据空间，
桥梁，
河流，
火焰，
云层，
远景。

但这些元素不能各自讲不同故事。

不要四宫格。
不要多个地图。
不要多个时空。
不要多个主要事件。

【构图】
根据主题、比例和机制，从以下结构中选择一种主要构图：

左文字 / 右场景，
上文字 / 下场景，
中心压迫，
远近距离，
对角线运动，
环形循环，
纵向攀登，
横向旅程。

不要平均混合多种构图。

构图必须明确形成：
角色 → 动作 → 目标 / 阻碍
的视觉阅读路径。

标题、地形、光源和环境结构共同引导视线。

【留白】
保留一块合理的海报留白区域。

留白可以来自：
天空，
黑暗空间，
雾气，
远景，
纯色墙体，
关卡之外的负空间，
巨大建筑表面。

留白用于容纳完整标题或强化情绪。

不要把每个区域都塞满像素细节。

【比例适配】
根据 {{图片比例}} 原生设计构图。

不要先生成一个固定横版场景，再裁切成其他比例。

16:9 / 3:2：
强化横向移动、角色与目标的距离关系和完整世界景深。
适合：
旅程，
方向冲突，
遥远目标，
追逐，
横向平台关卡。

标题可以进入左侧或右侧留白区域，
也可以成为远方建筑或地形的一部分。

4:5 / 9:16：
强化上下空间和垂直运动。
适合：
攀登，
坠落，
巨塔，
深井，
巨大系统，
垂直压迫。

目标可位于顶部、远方或深处。
标题位于顶部、中上区域或融入垂直建筑。

1:1：
集中为：
一个核心符号，
一个闭环地图，
一个巨大障碍，
一个角色与目标的直接关系。

缩短阅读路径，
强化缩略图识别。

自定义比例：
重新计算：
角色比例，
标题位置，
关卡长度，
目标距离，
视觉动线，
留白区域。

【标题】
用户输入的主题原文必须完整、准确地至少出现一次：

“{{主题原文}}”

不得省略、改写或生成错字。

标题使用清晰、稳定、适合海报阅读的像素字体。

标题必须与场景融合，
但不允许因融合而损害可读性。

不要把标题简单浮贴在游戏背景上。

标题可以成为：
建筑立面，
道路结构，
关卡边界，
巨大地形，
远方目标，
光源，
可破坏墙体，
平台，
入口，
环境标识。

也可以让：
机械局部遮挡标题，
角色站在标题结构上，
地形穿过字形，
标题产生受控像素故障，
光线从标题中射出，
某些字成为关卡结构的一部分。

【关键词强调】
从完整主题中选择 1–3 个最重要关键词。

可以通过以下方式强调：
放大，
改变颜色，
错位，
像素破碎，
局部发光，
阴影，
局部故障，
前后层级变化。

但完整主题原文必须保持清楚可读。

不要为了视觉效果破坏中文结构。

【辅助文字】
除了主题原文，
不要自动增加大量说明文字。

不要加入：
随机英文，
日期，
版本号，
关卡编号，
虚构开发商，
游戏名称，
品牌，
Logo，
宣传口号，
UI 数值。

除非用户输入中明确要求。

【Godot 2D 像素语言】
整体呈现为使用 Godot 制作的高质量独立游戏二维像素艺术。

视觉特征：
手工逐像素绘制感，
16-bit / 32-bit 视觉密度，
硬边像素，
清晰 Sprite，
统一 Tilemap 网格，
统一像素尺寸，
可信的二维关卡逻辑，
明确碰撞边界和平台关系。

角色、标题、地形、建筑、粒子、光影和道具必须共享同一套像素网格逻辑。

不能出现：
角色像素很粗而背景极细，
标题边缘平滑而场景是像素，
照片级元素混入像素场景，
矢量图形与 Sprite 混用。

【不是像素滤镜】
必须从像素艺术逻辑重新构建场景。

不要：
把普通高清插画简单像素化，
把 3D 渲染结果降低分辨率，
给照片添加马赛克，
用模糊滤镜伪造复古像素感。

场景要像真正被：
Sprite，
Tilemap，
像素粒子，
二维光照
构建出来。

【光影】
允许使用像素艺术内部的电影级光影。

可以加入：
分层远景，
体积感雾气，
局部火光，
窗口光，
夕阳，
月光，
数据光，
森林缝隙光，
黑暗中的单一光源。

但所有光影边缘必须服从像素语言。

保持硬边像素和有限色阶。

不要使用大面积平滑摄影模糊。

不要使用景深滤镜掩盖像素细节。

【环境叙事】
不用文字解释所有背景故事。

通过：
损坏建筑，
废弃设施，
远景目标，
反复出现的机关，
路径痕迹，
资源残留，
天气，
灯光，
地形变化
暗示世界观。

环境叙事必须强化核心机制。

不要加入无关 Easter Egg 或装饰剧情。

【色彩系统】
根据主题自动生成一套有限且统一的像素调色板。

避免所有颜色平均竞争。

建立：
1 个主要环境色，
1 个主体 / 地形色，
1 个深色结构色，
最多 1–2 个局部强调色。

根据主题可以偏向：

明亮冒险：
蓝天，
草地绿，
暖阳黄，
清爽浅色。

暗黑幻想：
深蓝，
黑，
暗红，
火焰橙，
低明度紫色。

科技未来：
蓝紫，
深灰，
数据蓝，
少量克制霓虹。

温暖成长：
黄昏橙，
紫色天空，
米色，
暖光，
柔和绿色。

孤独 / 压迫：
大面积低明度环境，
极小高亮目标。

颜色只服务主题、机制和情绪。

不要复制某个现有游戏的固定调色板。

【独立游戏气质】
整体应具有真正的独立游戏艺术气质：

作者性，
克制，
有世界观，
有情绪，
有游戏机制，
有环境叙事，
有一点诗意或哲学意味。

不要做成大型商业手游广告。

不要让画面充满：
奖励图标，
抽卡元素，
HUD，
商城按钮，
技能框，
数值信息。

【用途适配】
根据 {{用途}} 调整标题和场景复杂度。

公众号封面：
保证横向缩略图状态下，
完整标题和核心机制一眼可懂。

X 封面：
强化横向空间和角色与目标的距离关系。

小红书封面：
优先提高标题尺寸和视觉焦点，
控制背景细节。

视频封面：
加强角色动作、目标和冲突，
保证小尺寸识别。

海报：
可以增加环境叙事和世界细节，
但不增加第二隐喻。

【原创性】
画面只能借用通用的：
独立游戏像素语言，
二维平台关卡逻辑，
Godot 式开发视觉气质。

不要复制任何现有游戏的：
角色，
地图，
Sprite，
Tilemap，
UI，
Logo，
具体怪物，
具体道具，
具体关卡布局，
品牌识别元素。

不要出现 Godot 官方 Logo 或品牌标识，
除非用户明确要求。

不要复制参考游戏中的问号砖、道具槽、菜单面板或特定角色设计。

【必须避免】
不要写实摄影。
不要 3D 渲染。
不要普通动漫。
不要平滑矢量插画。
不要商业 PPT。
不要信息图。
不要普通封面模板。

不要：
四宫格，
多个故事，
多个主角，
多个主要隐喻，
复杂游戏 UI，
物品栏，
状态栏，
技能栏，
菜单界面。

不要大量文字。
不要随机英文。
不要水印。
不要 Logo。
不要错误中文。
不要模糊像素。
不要混用像素比例。
不要使用平滑边缘破坏像素网格。

不要让画面像直接截取的一张游戏截图。

必须具有：
海报级标题层级，
明确留白，
视觉焦点，
经过设计的构图。

不要加入 {{可选禁止元素}}。

【生成前检查】
生成前内部检查：

是否只表达了一个核心观点？

是否能够用一句话说明这个游戏机制？

角色是否只有一个主要动作？

目标或阻碍是否明确？

观众能否理解“如果我是玩家，我会经历什么”？

标题原文是否完整准确？

标题是否与场景发生关系，而不是浮贴在画面上？

像素比例是否统一？

是否存在不必要的 UI？

是否意外复制了现有游戏视觉资产？

如果删除某个元素不会影响机制表达，
删除它。

【最终标准】
最终画面必须像一个真实存在的高质量独立游戏宣传海报。

必须同时具备：

1 个可体验的游戏机制隐喻；
1 个主要角色；
1 个明确动作；
1 个目标或阻碍；
1 个核心视觉焦点；
1 个完整像素世界；
1 套统一像素调色板；
用户输入的完整主题原文；
专业、清晰的海报级标题排版；
明确的世界观与环境叙事；
清楚的情绪张力；
足够强的视觉记忆点。

最终观感不是：
“把主题画成像素图。”

而是：
“如果这个观点是一款二维独立游戏，它最重要的一关会是什么样子？”

只生成一张最终图。

不要输出：
分析过程，
解释文字，
多个方案，
拼图，
网格，
联系表，
游戏 UI 展示，
角色设定页。
````
