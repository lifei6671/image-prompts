````text
# 白板手绘知识图解

## Prompt

```text
创作一张“白板手绘知识图解”风格的信息图。

整体视觉像老师、技术作者或科普博主在一张白色画纸上，
用黑色马克笔和彩色荧光笔，
把一个复杂概念拆成几个简单模块并手绘出来。

画面重点不是精致插画，而是：

清楚，
直观，
容易理解，
有手绘感，
像真正的人一边思考一边画出来的知识草图。

【输入】
主题 / 标题：{{主题}}
核心知识点：{{需要解释的概念、流程或关系}}
关键步骤：{{可留空；由内容自动拆分}}
核心结论：{{可留空}}
画幅比例：{{默认 16:9}}
语言：{{中文 / 英文 / 中英混排}}
可选强调内容：{{希望重点突出的位置，可留空}}
可选禁用元素：{{不想出现的元素，可留空}}

【整体风格】
使用纯白偏暖或极浅米白背景。

背景干净，
保留大量自然留白，
像白板、讲义纸或轻微纸张纹理的教学草图。

主要使用：

黑色马克笔式手绘线条，
略微不规则的矩形框，
手绘箭头，
虚线，
分隔线，
简单表格，
流程连接线，
手写标签，
少量彩色模块。

线条不要完全笔直，
保留轻微抖动、粗细变化和真实手绘感。

不要做成精准矢量图。

【知识结构】
先理解内容，
再把复杂知识压缩成 2–5 个最重要的步骤、对象或关系。

优先使用：

从左到右流程；
从上到下流程；
输入 → 转换 → 输出；
概念 A → 中间过程 → 概念 B；
对象之间的映射；
步骤之间的因果关系；
对比关系；
层级关系。

整张图只解释一个核心知识点。

不要同时塞入多个复杂主题。

【模块】
每个知识模块使用简单手绘框表示。

模块可以包含：

关键词，
短句，
小卡片，
简单矩阵，
列表，
表格，
图形符号，
概念块。

框体使用黑色细线或中等粗细线。

边角可以略圆，
但保持随手绘制的感觉。

不要使用商业 UI 卡片风格。

【流程箭头】
模块之间使用简单黑色手绘箭头连接。

箭头可以搭配极短说明文字，例如：

分词
编码
映射
查询
输入
转换
输出
匹配
计算
生成

这些文字直接写在箭头附近。

不要使用复杂流程线，
不要大量交叉连线。

让读者能够沿着一个明确方向读完整张图。

【颜色系统】
整体以黑色线稿为主。

只使用少量低饱和、柔和的粉彩色作为知识分类和重点提示。

建议使用：

浅绿色，
浅蓝色，
柔和黄色，
淡粉色，
浅橙色。

颜色主要用于：

关键词卡片，
步骤块，
表格行，
重点框，
少量强调符号。

同一概念在不同区域保持同一种颜色，
形成视觉对应。

例如：

概念 A 始终使用浅绿；
概念 B 始终使用浅蓝；
概念 C 始终使用浅黄；
概念 D 始终使用淡粉。

不要使用高饱和霓虹色。

不要让颜色铺满整个背景。

【文字】
所有文字必须清楚、准确、可读。

整体使用手写马克笔 / 手写讲义式字体气质。

中文像：
自然手写黑体，
白板笔书写，
教学笔记字体。

英文像：
简单手写体，
marker handwriting，
casual handwritten sans-serif。

标题可以略大、略粗。

步骤标题明显大于内容文字。

不要使用：
复杂书法，
花体，
商业海报字体，
机械印刷感很强的字体。

【中英文混排】
如果内容包含英文技术术语，
保留原始英文，例如：

Token
Token ID
Embedding
Vector
Input
Output
Model

中文解释与英文术语可以自然混排。

英文术语可以作为模块标题，
中文负责解释。

不要为了装饰加入随机英文。

【图形表达】
优先用简单图形解释概念。

可以使用：

色块卡片，
格子矩阵，
数组，
表格，
小方块，
路径，
箭头，
分隔线，
数字，
简单符号。

复杂结构要进行高度简化。

例如：

向量可以表现为一排小色块；
矩阵可以表现为规则格子；
数据可以表现为几张小卡片；
层级可以表现为上下结构；
映射可以表现为两组对象之间的箭头。

不要追求真实技术界面。

重点是帮助普通人理解。

【小人物】
可以在画面边缘加入最多 1 个极简火柴人或手绘小人物。

人物只是轻松的视觉点缀，
可以：

指向结论，
举手，
观察流程，
站在说明框旁边。

人物使用最简单的：

圆形头部，
两点眼睛，
简单微笑，
线条身体和四肢。

不要让人物成为主视觉。

如果不需要人物，
可以完全省略。

【结论框】
如果内容存在一个特别重要的结论，
可以在画面底部或大片留白区域加入一个横向手绘结论框。

结论框：

使用简单黑色圆角线框；
内部只放一句最重要的话；
字号明显大于普通说明文字；
保持简洁。

例如结构：

“{{核心结论}}”

它负责告诉读者：

“这张图最应该记住什么。”

不要写成长段文字。

【构图】
16:9 横版优先使用：

左侧：
输入 / 起点 / 概念 A。

中间：
转换 / 映射 / 中间步骤。

右侧：
结果 / 输出 / 概念 B。

底部：
一句核心总结。

整体形成：

概念
→
过程
→
结果
→
结论

的清楚阅读路径。

模块之间保持足够距离。

不要把框体挤在一起。

不要把整个画面铺满。

【信息密度】
信息量保持中低密度。

每个模块只保留最必要内容。

优先：

关键词，
短句，
示意图，
关系箭头。

减少：

长段文字，
复杂公式，
大量注释，
多层嵌套。

如果一个知识点无法在几秒内理解，
继续简化。

【手绘感】
必须明显表现出人工手绘痕迹：

线条轻微抖动；
矩形边缘不完全笔直；
箭头有自然手绘弧度；
字体略有大小差异；
线条连接处不完全机械；
色块像淡淡的马克笔或彩笔填充。

但整体仍然必须：
整洁，
稳定，
容易阅读。

目标是“专业作者的手绘教学图”，
不是儿童乱画。

【生成前检查】
生成前内部检查：

是否只解释一个核心概念？

是否可以拆成 2–5 个主要模块？

阅读顺序是否明确？

箭头是否足够简单？

不同概念是否用一致的颜色编码？

技术术语是否准确？

标题是否清楚？

是否存在一句值得单独强调的结论？

是否保留了足够留白？

是否出现太多无关装饰？

如果删除一个元素不会影响理解，
删除它。

【必须避免】
不要做成商业信息图模板。

不要做成 PPT 风格。

不要精确矢量 UI。

不要复杂渐变。

不要 3D。

不要写实插画。

不要大型人物。

不要复杂背景。

不要大量图标。

不要密集公式。

不要过度装饰。

不要加入：
Logo，
水印，
随机英文，
无意义编号，
复杂小字。

不要让画面拥挤。

不要让线条过于机械笔直。

不要加入 {{可选禁用元素}}。

【最终标准】
最终只生成一张完整知识图解。

画面必须同时具备：

纯白偏暖背景；
大量干净留白；
黑色马克笔式手绘线条；
2–5 个清晰知识模块；
明确的流程箭头；
少量浅绿、浅蓝、浅黄、淡粉等粉彩色块；
清楚准确的中英文文字；
简单手绘框、表格或矩阵；
可选的极简火柴人；
一句可选核心总结。

远看时：
首先看到清楚的知识结构和阅读路径。

近看时：
看到自然手绘线条、彩色分类、技术术语和关键解释。

最终效果应该像：

一位很会讲复杂问题的老师，
拿着黑色马克笔和彩色笔，
在白板上用最简单的几个框、箭头和色块，
把一个复杂知识点讲明白了。

不是“精致的信息图设计”，
而是“让人一眼就能看懂的手绘知识解释图”。
````
